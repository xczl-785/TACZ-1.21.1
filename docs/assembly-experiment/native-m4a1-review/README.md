# 原生 TaCZ M4A1：拆件与动作审查

2026-09-16。**这是审查方案，不是已接入枪械。** 四项已确认决策见文末；剩余效果附件与LOD结论见[补查报告](补查结论.md)。 对象是 `tacz:m4a1`，不是 `newmod_m4a1`。未改生产源码/模型、制品、运行锁或 Blockbench；未启动游戏。第一、二项已由用户联合接受。

## 结论先看

可保留原生 140 骨骼及原动画，只给立方体增加实体归属；物品安装树与动画骨骼树分别维护。建议默认完整装配有 **15 个实体节点（含下机匣根物品）**，不是旧 18 个分区各发一个物品。精细的小销、扳机、释放钮和导气座内部细件先随所在总成，继续保留动画。

三项容易误判的事实已查清：

1. `receiver_remainder` 的 214 立方体可以完整拆账为 **下机匣 78、上机匣 82、导气座/管 36、连接环 18**。没有“剩下的先塞机匣”未归属几何。
2. 原分区 `stock` 的 68 个立方体属于 `attachment_adapter/oem_stock_tactical`。现存附件请求的是 `ar_stock_adapter`，不是这个节点；原枪没有内置枪托，开发领取也不装枪托。因此这 68 个是当前资源组合下不会显示的备用几何，不能当原默认枪托。完整新预设建议选用现存 `tacz:stock_tactical_ar`；原裸枪保留对照。
3. 85 是全保留附件数，M4A1 当前递归标签允许 **55** 件：瞄具15、枪口9、前握把12、枪托9、激光4、扩容类别6。不能把其余30件一并放开，也不能因旧 `m4a1_stock` 标签只列5件就缩成5件——当前 allow 表引用的是通用 `#tacz:stock`。

[逐组几何图](receiver-groups.png)是按引擎骨骼/立方体旋转规则生成的离线无纹理投影，每格独立缩放；[默认形态归属图](native-default-ownership.png)省去表现弹药和手臂，保留原裸枪形态。它们用于实体判断，没有冒充 Blockbench 或实机画面。

## 4. 原生动作如何保持

安装树管理物品，原140骨骼管理动作；两棵树不得互相替换。每个立方体归属一个实体，但同一实体可跨多个原骨骼。例如前准星跨sight与sight_folded，枪机仍在m4a1_pull下面受其检视动作带动。

渲染条件 = 实体已安装/启用 AND 原生可见性条件。保留一套完整原生骨骼，不为每个配件播放一套动画；拆拉机柄只关pull所属立方体，不关闭m4a1_pull整棵动画树。手臂2块为功能定位替代渲染，表现弹药36块、相机、枪口/抛壳/视角挂点不注册为物品。

| static_idle | .0667 | 双手与constraint静态姿态 |
| static_bolt_caught | .6667 | bolt_release与m4a1_bolt；空仓挂机轨道 |
| static_auto / static_semi | 未显式声明 | selector静态快慢机位置，不把缺少length当作无动画 |
| switch_auto / switch_semi | .6667各 | selector、双手、root、camera；与开火/装填/检视的轨道停止规则 |

17段计数包括表中合并列出的成对动画。[机器表](ownership-proposal.json)列出每段完整目标和通道，以及经过骨骼祖先传播后影响的实体。原生 `m4a1_state_machine` 继承 `default_state_machine`；display还使用rifle默认动画和第三人称default。因此“复制17段”不足以保真，相关默认轨道、状态机、音效触发及服务器reload脚本必须继续使用。

- 空/战术换弹由膛内弹+弹匣余量选择；扩容等级0选普通，1–3选xmag动作。
- 动画长度不是扣弹/填弹时间。`xmag_reload_logic`及gun data另有feed/cooldown：默认战术1.40/1.87，默认空仓1.87/2.2；扩容战术1.46/2.29，扩容空仓2.29/2.67秒。必须保留服务器时机与原动作相位，不能按动画结尾才填弹。
- `additional_magazine`在动画中用于画第二个弹匣，原renderer复制当前magazine可见内容，不是第二个库存实例，不产生物品。

| --- | --- | --- |
| SCOPE | 28 /15 | upper/scope；保留原附件模型、镜内与倍率 |
| STOCK | 9 /9 | buffer/stock；同一现有ItemStack |
| GRIP | 12 /12 | upper/barrel_mount/handguard/foregrip；不是手枪握把 |
| LASER | 4 /4 | handguard/laser；保留颜色等附件状态 |

| EXTENDED_MAG | 17 /6 | 唯一弹匣位置，保持其原ID/等级/修饰数据，不另存一份“扩容插件” |

两个必须显式处理的特例：

- 6个扩容类别分别为extended_mag_1/2/3与ammo_mod_fmj/hp/i；后三者原生数据都带等级3。它们是现存附件的遗留属性机制，不等于本次86种实际塔科夫弹药。补查发现容量/重量/ADS仍生效、速度被真实弹种覆盖、伤害按目标分支分流、I点燃独立残留，不能当作普通弹匣。建议仅新实验枪禁用这3项、保留全局85件及旧枪规则，不自动转换；该限制待用户裁决，详见补查报告。
- M9刺刀会保留默认枪口体，不能把它当普通替换枪口。建议树中保留默认枪口实体，刺刀作为其子件；与其他MUZZLE外部装置维持原互斥。Z装刺刀要求默认枪口在位；切换其他枪口时一次事务返回刺刀及被替换默认实体。拆父件返回完整子树。新增的默认实体是真实财产，不能为了仿旧界面让它免费消失或免费再生。这个比旧“只有一个附件槽”更明确的物品返还语义必须用户确认。

**唯一权威建议：foundation AssemblyComponents.STATE 中的安装ItemStack树。** 库存扣还仍通过tactical TacticalHeldExchange。TaCZ的附件查询是这棵树的投影，不在GunAttachment*自定义NBT再保存同一附件副本。

生产接入必须一起覆盖 `getAttachment`、`getAttachmentId`、`getAttachmentTag`、`setAttachmentTag`、安装/卸载写入口及属性更新。只覆盖getAttachment会导致镜片倍率、激光颜色和HUD仍读取旧NBT。投影返回副本；颜色/倍率等更新写回树中同一实例，不让客户端修改副本变成权威提交；保留现有网络校验。按槽查询需要同时处理默认件与空槽映射。

原Z界面和实体工作台可以作为两种视图，共用一次服务端会话/交易入口：Z的scope/stock等槽映射到树路径，安装或拆卸走同一报价、token消费、原子交换、失效检查；不能同时让原RefitBridge直接installAttachment写NBT、另一边AssemblyGunExchange写树。属性postChangeEvent只在提交成功后触发一次。原生对照枪继续走现有Z，不改变它的数据。

新样本不能直接塞进旧AssembledWeapons就完事：当前RefitBridge.ready明确排除其枪，AssemblyGunClient又截获Z并强转AssemblyGunModel；当前定义按注册物品ID匹配，而85附件共用tacz:attachment，实际类型在附件ID中。需要抽出“持有枪的组装定义/实例身份/附件定义解析/视图”边界，支持读取IAttachment附件ID并为安装实例分配稳定身份，避免把所有附件识别成同一个型号。旧三枪仍用现有配置策略，不重写其资产。

## 7. 可以复用与不能直接套用

**复用**：weapon_assembly规则与路径验证、foundation真实装配/实例、tactical原子交换、服务端会话/防重放、AmmoBridge弹种与余弹合同、WeaponRuntime开火门槛、工作台交互/选择逻辑、现有原生枪与附件渲染/动作/声音/抛壳/瞄具机制。

**不能直接套用**：旧三枪已烘焙三角网格的ModelGeometry坐标与meshScale、矩阵组件转换器、AssemblyPresentation对手与机瞄/后坐力的二次覆盖、简化红点、AssemblyGunClient对AssemblyGunModel的强转。它们需要保留原行为并提取可插拔显示/定义接口，原生样本走Bedrock原生骨骼和原动画。离线UI若需三角预览，可从原生立方体生成只读预览数据；它不是枪在手上的新事实源，预览与原生部件映射须同表生成。

## 8. 当前裁决与后续边界
