# 旧效果附件与原生 LOD 补查

2026-09-16。承接用户确认的15默认节点、CTR/30发空弹匣、核心禁射与膛内一发规则、两种真实护木。**只读补查，以下推荐仍须主控派发后实施。** 不再建议把三个旧效果附件直接当弹匣，也不再建议未经LOD审查就使用全距离高模。

## 一、FMJ / HP / I到底做了什么

这三个ID是 `tacz:ammo_mod_fmj/hp/i`，类型为EXTENDED_MAG；display只有槽位图与装卸声，没有独立实体模型。它们不是86种塔科夫弹药，也不是可直接等价转换的普通弹匣。

### 配置到执行的完整链

附件ItemStack → `getAttachmentId(EXTENDED_MAG)` → 附件数据与AttachmentPropertyManager各修饰器缓存 → 服务器脚本/子弹构造与命中。

与此同时，战术库存消费实际弹药 → AmmoBridge把实际弹种ID写入枪 → 构造子弹时snapshot取该弹种的fleshDamage/penetrationPower/armorDamage → BulletImpactEvent → combat报价/提交。snapshot没有读取这三个附件的damage或armor_ignore。

| 属性 | FMJ | HP | I | 在当前接管链路中的结果 |
| --- | --- | --- | --- | --- |
| 扩容等级 | 3 | 3 | 3 | M4A1容量60、三级弹匣显示、xmag动画及时机，实际生效 |
| weight | +0.6 | +0.6 | +0.6 | TaCZ重量缓存及tooltip生效；重量移动系数开启时影响原生移速。不是本报告证明的战术物品净质量 |
| ADS时间 | +.02秒 | +.02秒 | +.02秒 | 原生瞄准缓存生效，非纯外观 |
| damage | ×.9 | ×1.3 | ×1.1 | 修改原生伤害距离表；combat成功接管的身体/护甲报价不采用这个表 |
| armor_ignore | x>.5乘1.5，否则乘1.75 | ×.5 | ×.8 | 修改原生穿甲伤害比例，最后clamp0..1；不是塔科夫penetrationPower |
| ammo_speed | ×1.1 | ×.9 | ×1 | 原生缓存仍计算，但实际弹种有效时被ScriptAPI最后覆盖为该弹种initialSpeed，再乘全局速度系数/发射倍率 |
| pierce | x>2加2，否则原值 | ×0 | 不改 | 是原生可继续碰撞的穿透次数，不是护甲穿深；实体构造至少clamp到1 |
| ignite.entity | 不改 | 不改 | true | 独立于combat伤害报价，命中Pre未取消且配置允许时，在伤害提交前执行点燃与粒子 |

数值例只用于解释缓存，假设没有其他附件/脚本倍率、伤害基础倍率为1、近距离：M4A1原伤害6.5，FMJ/HP/I变5.85/8.45/7.15；原armor_ignore .2变.35/.1/.16；重量3.5变4.1，ADS .16变.18；原pierce1三者最终都还是1。**不能把这些数字当玩家实际受伤量。** HP缓存先变0，再被构造函数恢复为至少1；FMJ“增加穿透”在M4A1默认pierce1下不触发。

### 重复/覆盖的位置和残留差异

1. **速度覆盖明确**：ModernKineticGunScriptAPI.modifyProperty先调用原属性修饰，再在有效AmmoBridge.definition存在时返回entry.initialSpeed。例M855始速922，三种附件均不能把它再乘1.1/.9；最终还有全局速度和projectileSpeedMultiplier。不是“附件根本没加载”。
2. **身体伤害/护甲分支**：AmmoBridge.snapshot把M855的54/31/37传给combat；PlayerCombat在能解析玩家姿态、防护资源可用时据此报价。TacticalTaczAdapter.prepareFeedback更新原Pre事件反馈；EntityKineticBullet.adapter$apply在报价被接管且目标仍匹配时提交报价，不调用原生伤害拆分。因此附件damage和armor_ignore没有再次乘到这份报价上。
3. **原生回退仍存在**：普通未接管生物、无法建立报价的玩家状态/资源、被Pre改成其他目标等，仍可能走tacAttackEntity；ITargetEntity在更早分支直接显示getDamage。上述5.85/8.45/7.15和原生armor_ignore可在这些分支影响结果。同一实际弹种不会因此在所有目标上一致使用同一套属性，这是当前既有边界；本次不暗改全局战斗规则。
4. **I不是“被覆盖后无效”**：点燃在Pre通过后、adapter$apply之前执行，combat报价没有覆盖它。即使实际弹种没有燃烧属性，附件仍可能附加点燃/粒子；最终健康效果受原版火焰、免疫等规则影响，未实机测量。代码将igniteEntityTime直接传入setRemainingFireTicks，不能凭字段名承诺几秒持续燃烧。
5. **穿透两种含义不可混用**：PIERCE控制原子弹命中循环与剩余次数；combat的penetrationPower/armorDamage控制护甲结算，跳弹还有其独立续弹报价。不能把FMJ的+2解释成真实弹药穿深+2。

结论不是“数值总会重复相乘”，而是**部分被覆盖、部分仍生效、部分按命中目标走不同分支**。把这三件当普通60发弹匣会把这个不一致机制带入新实体装配。

### 推荐：限制新样本，不改旧资产

- 新实验M4A1只接受 `extended_mag_1/2/3` 与新的标准实体弹匣；**不接受ammo_mod_fmj/hp/i**。新样本从原55件候选中排除3件，成为52件；全局85件仍完整保留。
- 三个旧ID、物品、槽位图、语言、声音、旧枪适用规则不删除，不转成塔科夫弹药，也不自动换成extended_mag_3。它们保留为旧对照环境的效果附件；新样本安装请求给出明确不支持原因。
- 不自动转换的原因：普通extended_mag_3为weight+.8、ADS+.045，而旧效果件为+.6/+.02并带上述特殊效果，二者不是等价财产。若以后统一退役，必须另行裁决存量补偿/转换与全球枪械影响。
- 不推荐仅把效果清零后仍叫FMJ/HP/I弹匣：名称、原物品承诺和外观来源不匹配。也不推荐本项新增“弹药效果插件槽”，那会引入第二个弹种机制。
- **需用户裁决的实质变化**：新实验枪相较原生对照少接受这3件；原生对照行为不变。这比保留误导性“六款扩容弹匣”更符合真实弹种所有权。

## 二、LOD可做，但不能原样套同一骨骼名

当前高模140骨骼/1006立方体，原LOD只有28骨骼/75立方体。高模17段动画的目标不具备同名LOD绑定；这不代表现有第一人称动作已经坏了——第一人称直接使用高模，不选LOD。

### 75个立方体逐个处理结论

[supplement-evidence.json](supplement-evidence.json)保存全部 `(bone,cubeIndex)`，无重复、无漏项，47+28=75。

### 推荐正式方案：同一实体清单，两套渲染表示

1. **实体ID/安装路径/可见性条件是一份**；高模和LOD各有 `entity + variant + nativeAnimationBone -> geometry batches` 映射。LOD不得复制持久化装配状态，不按距离改变库存或能力。
2. 新LOD派生文件使用原高模的完整功能骨骼/挂点骨架，几何可以是低模。47块候选低模经“原低模局部→共同世界→目标原生骨骼局部”的逆变换重绑定；校验中立姿态顶点位置保持，不直接改parent后沿用旧局部坐标。控制件需要继续绑定相应动画骨骼。
3. 28块混合/不合适区域不硬分给某件：按高模已有实体归属生成独立低模连接环、枪管/枪口、导气座、前准星立起/折叠、两种护木。补齐低模枪机与三种扩容外形；内件即便远处省略几何，也必须显式声明LOD不可见，不能借不存在几何判定“没安装”。
4. 纹理不能直接互换UV：复用旧LOD块保留旧LOD纹理及UV；重新简化的部件要保留或重新烘焙其来源纹理。可按材质批次使用两张atlas，也可离线统一烘焙派生atlas；以最终视觉误差和批次数验证，不能用原高模UV读旧低模贴图。
5. CTR等原生附件通过AttachmentRender按实际ItemStack加载。**当前CTR display没有LOD**，该附件本身保留原模型是现有可持续的逐附件回退，不代表整枪全距离使用1006块高模。以后单独补附件LOD仍复用同一装配ID。
6. 生产首交付就包含按实体分开的LOD和缺件校验；不采用全距离高模作为默认方案。实际低模立方体/面数应由生成器报告并与高模相比，不能现在把75当作完成后的性能指标；没有FPS测量就不承诺性能提升幅度。

### 各视角与加速渲染怎么接

- 第一人称：GunItemRendererWrapper.renderFirstPersonInner始终取display.getGunModel，更新原状态机；高模遮罩不得覆盖原动画。
- 第三人称/地面/展示框等：通用render按距离选择高模/LOD；两者都必须在绘制前读取当前实例的同一装配投影。
- 物品栏GUI目前用slot图，不是3D LOD；原生改装/工作台3D预览应明确使用同一装配投影，GUI高模距离标记不等于已验证所有UI。非支持副手分支当前直接返回，不扩大本项功能。
- 原生附件有自己的LOD选择，且第一人称不降附件LOD；保留镜内模板、光学倍率、挂点和父实体存在性。
- **加速风险已经定位**：BedrockPartMixin在compile开头取消普通循环，用 `Map<IBufferGraph,IMesh>` 缓存整个part的cubes；这个key不含装配状态。运行中改cubes列表或只改普通compile循环，会复用旧全量网格。
- **推荐解决方式**：每个 `原动画骨骼 × 实体 × 外观变体 × 材质` 建不可变几何叶片/批次；隐藏在提交绘制之前发生，原动画骨架保持可遍历。普通与加速路径提交完全相同的可见批次；每个批次独立稳定mesh缓存，不因另一把枪的装配改变缓存内容。不要把整棵gun_body或m4a1_pull关掉，也不要把全体装配组合纳入无限增长缓存。
- 加速兼容仅在acceleratedrendering存在时生效；需要该环境单独验证两把枪不同装配切换、换LOD后缓存不串件。此次没有启动该环境，不能声称加速实测通过。

### 可验证门槛与裁决

可延续方案成立，**没有发现必须全距离高模的技术阻塞**；必要工作是47候选块重绑定、28混合块替代、缺失变体与功能骨架补齐、普通/加速统一批次门槛。它是明确制作/接入工作，不是“已有LOD可直接用”。

生产前的静态验收至少包括：两表示实体ID集合相同或有显式省略理由；每块几何只归一个实体/变体；所有必需挂点齐全；中立姿态重绑定误差在约定阈值；高低模同一次缺件查询不会提交不同实体；护木两型、四弹匣、前准星两态、M9与默认枪口组合；缓存不依赖前一次持枪实例。纹理/切换轮廓、帧率和加速环境最终由用户实机验收。

剩余实质裁决：是否按推荐**只对新实验M4A1禁用三个旧效果附件**。LOD不再请求用户接受全距离高模的临时取舍；建议主控把上述正式派生LOD工作纳入第三项生产合同。若后续具体几何制作发现无法满足阈值，再提交具体问题，不能先无证据降级。
