# 默认 M4 配件导入复盘

2026-09-16；参与：用户负责需求与实机验收，Codex 负责模型整理、导入与工程检查。

目标：默认整套 M4 拆为独立可编辑模型，携带纹理重新接入游戏；用户直接启动查看。

结果：15 件、583 方块已作为独立编辑源；工作台、图标、持枪高低模已接入 NewMod。源码提交 `9da6cb13`，交付证据 `a7944d8e`，NewMod 接入 `e2da871`。83 Java 测试、15 件 Blockbench 往返及正式/开发启动准备通过。用户认可这套思路；不将该表述扩大为所有视觉、动作和低模场景均已实机接受。

## 问题与经验

- 原生方块被旧导出合并成三角网格，形状仍是模型，但不利于逐块编辑。此次直接提取原生方块作为编辑源，三角网格留给生成阶段。
- 旧导出把 PNG 像素尺寸当成 UV 单位。M4 实为 256 UV 对应 512 PNG，CTR 为 64 对应 128；此次按模型 UV 单位归一化。其余候选仍属后续批次。
- Blockbench 保存会将坐标保留到约五位小数。最初独立配件使用高精度中心，保存往返会产生细小差异；改用五位小数中心后，15 件坐标/UV 往返检查通过。
- CTR 是其他枪共用的原生配件。此次只在组装 M4 内接管其显示，并在切换备用枪托时保留原生渲染；未改共享配件身份或其他枪。
- 早期总览铺得太散、视角不便查看。后续区分可编辑分件源、整枪查看副本和拆解查看副本，明确后两者不回写。

保留：一套编辑来源生成多处显示；逐件记录来源/安装位置；工程验证与用户实机验收分开。改进：把朝向、透明度及纹理采样作为图标生产合同。停止：手工分别维护图标/工作台/持枪三套几何，或从三角网格反推已有原生方块。

## 下一轮明确要求

用户指定：所有配件图标假设配件已装到枪上，整枪枪口朝左，配件保持该姿态。枪管枪口端向左、枪托尾垫向右；不能把每件自身的长边各自随意转向。应调整统一渲染相机/投影，不镜像成品图片以免文字和非对称结构翻转。

现有 `render_part_icon.py` 的屏幕横轴以 +Z 为正，当前制作坐标又是 +Z 枪口，因此会把枪口投向右方，需要调整。该渲染器还以 RGB 读取纹理；下一轮要核对并保留透明像素，避免透明区域被画成实色。

负责人：Codex。后续先完成图标方向和透明采样的离线比较，再生成、打包接入；用户查看枪管、护木、弹匣和枪托的代表图标后决定是否继续扩展候选。范围仍从默认 M4 开始，共享图标工具的其他枪影响需明确审查。此复盘只记录要求，尚未修改图标实现。
