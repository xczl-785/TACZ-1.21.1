# 原生组装 M4 整枪显示链路

2026-09-16。用户报告第一人称正常，第三人称、快捷栏及装备栏只显示下机匣；授权修复整条显示链路，打包接入后由用户实机核实。

## 原因与修复

根物品同时是装配树的下机匣。原生成器给所有配件物品生成普通图片入口，误把根物品的整枪入口写成 `minecraft:item/generated` + `lower_receiver`。该状态在 e3504041 已存在，早于本次图标朝向修正；没有当时实机第三人称证据。

生成器现在按 weapon.json 的 rootDefinition 区分整枪和独立配件。整枪使用 builtin/entity，恢复原有第三人称、掉落物、展示框及高低模选择路径；第一人称仍使用原生骨骼/动画。独立配件图标保持自身外观。

GUI 读取当前启用的实体装配树，以工作台的中立几何、安装位置、UV 和材质生成枪口向左图标。工作台与图标共同读取 `data/tacz_fork_tarkov/<枪>/preview.json`、`library.json` 和 `materials.json`；不再生成第二套 icon_geometry/library/materials。纹理仍从当前资源管理器加载，透明像素在深度写入前裁切。

缓存按枪型、槽位和配件定义区分，不包含实体 UUID、弹药量或动画时刻。同样配置共享图标；拆装/启用状态变化产生新键。最多保留 128 张 256px 图标，淘汰时释放纹理；资源重新加载清空图标、源纹理与几何材质缓存。当前外观由配件定义及资源材质决定；若以后引入逐物品涂装，需要把该外观状态加入键。

装备栏复用 ItemModelBounds 的已有接口，以图标非透明像素的边界居中/等比缩放，避免把完整枪缩在长栏位的正方形中。NewMod 通用库存接口不增加枪械专用判断。

## 验证与边界

离线回归覆盖真实资源完整枪、拆掉枪托、裸机匣三张图；方向、透明前景不遮挡后方、纹理采样、透明边界、UUID/弹药不影响外观键、拆装改变键；高低模可见配件集合在完整/无枪托/裸机匣间切换与还原。构建与制品接入证据见 evidence/display-delivery.json。

离线图片及模型集合检查不是实际第三人称或显卡渲染验收。未启动客户端、服务端或修改世界。用户重启后检查：

1. 同一把完整 M4：第一人称、第三人称、快捷栏、装备栏、掉落物及展示框均显示整枪。
2. 拆掉枪托再装回：第三人称与栏位同步变化；另放一把不同配置的 M4，两者不互相串图。
3. 裸机匣保持裸机匣，栏位无明显裁切；较远第三人称检查低模。
4. 资源重载后图标恢复；第一人称射击、换弹维持原有表现。

本轮仅解决原生组装 M4 的显示接入，不批量制作候选配件，不改 ADAR/雷电的图标策略。瞄具制作继续留到其他配件之后。现有瞄具候选仍使用工作台中立预览；动态折叠/镜面效果的图标一致性留在瞄具阶段核对。
