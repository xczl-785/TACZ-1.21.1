# 非瞄具批量制作与框架加固

2026-09-16。用户认可上一轮整枪显示实机效果，授权继续推进并自行分派 subagent。兼容范围为 TaCZ 原版枪械经实体组装后的机制；不要求兼容 ADAR、雷电等旧导入路线。

## 本轮结果与边界

显示容错：异常身份、坏装配、资源缺失或空图回退到原生图标及名义边界，避免拖垮库存；失败与成功缓存分开，失败记录限量、限频诊断和重载清理。动态图标以 assemblyIcons 显式启用，不再与 nativeRig 骨骼类型绑在一起。

配件路由：NativeAssemblyProfile 从每枪 native-profile.json 读取引擎附件类型对应的物理槽位，以及刺刀等嵌套覆盖关系。原本写在 Java 中的 M4 路径转入源配置；加载时核对路径在本枪目录中可达。机械瞄准的前后配对/光学独立条件保持，只把既有判断转入配置。启用状态由同一实体装配树读取；禁用刺刀不再遮住父枪口读路径。规则检查含改名槽位树，证明解析器没有依赖 M4 名字，但不等于已接入第二把实际枪。

批量模型：新增战术护木及8种非默认枪托（AK12、Carbon Bone C5、HK Slim Line、M4SS、Militech B5、MOE、Ripstock、SBA3）。新增830方块，总24件编辑源、1413方块。脚本读取已审计的原生骨骼/方块索引，复制原PNG并按原生UV单位转换；重复运行不覆盖已有编辑。所有新枪托拥有独立rig/几何叶节点，由真实安装身份选择；持枪高低模、工作台和图标一并生成。原始共享TaCZ附件资源与默认15件编辑源不改，默认组合不自动装上替换候选。

源入口：`modules/tacz_adapter/weapon-sources/native_m4a1/editable/components/`；路由源：同级上层 `native-profile.json`。批量工具 `tools/native_m4a1/batch_editable.py` 当前仅开放已核对的首批清单；扩大清单前需核对来源、骨骼运动与安装变换，遇到例外停止该件而非猜测转换。

- 9件实际在Blockbench独立load/compile，恢复原项目，无写回用户源；编译结果重新导入的逐方块位置误差0，UV一致。
- 15旧模型/纹理与前一提交逐字节一致；两次完整生成的相关资源哈希一致；未修改原始共享附件。
- 100 Java测试、原3项编辑源及5项批量模型测试、14制作链测试通过；新增测试覆盖异常库存物品、失败缓存、路由配置与9种枪托高低模互斥显示。

## 第二批非瞄具（2026-09-16）

用户已实机确认首批9件无误，授权继续批量制作。第二批限定M4现有兼容清单中的28件：12握把、8枪口、4战术激光、3扩容弹匣、1 M9刺刀；不新增枪械，15件光学瞄具/红点继续延后。

编辑源累计52件2447方块，本批新增1034方块。25件外置附件生成独立原生Bedrock模型与独立PNG，由每枪 `native_attachment_overrides.json` 选择。渲染复用原生附件模型入口，保留激光空骨骼、安装点旋转、光束颜色/开关等行为；3扩容弹匣保留M4原生magazine动作归属。已有9种枪托内嵌路径保持。这个选择避免把激光等功能节点压成纯静态几何，也不修改其他枪共用的附件资源。

`NativeAttachmentModels` 只装在对应组装枪模型实例上，无全局附件替换、无具体配件ID分支。未在清单内的附件继续走原生渲染，光学瞄具保持原生镜内链路。本批不宣称已验证第二把枪；每枪rig叶节点和折叠规则配置化仍在后续路线。

28件已实际在Blockbench独立加载/编译后再导入，逐方块位置差0、UV一致，用户原项目已恢复。最终101项Java、11项模型Python检查及check/assemble通过；NewMod开发964/正式923类，依赖与启动准备、配置缓存复用通过。本批实机待用户，见 [证据](evidence/remaining-delivery.json)。
