# 以自有枪械闭环为目标的冲突盘点

> 边界依据与历史诊断：枪械各自闭环、公共玩法独立的责任约束继续适用；2026-09-15 的类/路径、缺失能力和“下一步迁入 adapter”是当时快照。合并结果见[当前索引](README.md)，自有枪械的现状必须在其独立工程核对；本文不替代其当前基线。


2026-09-15，仅代码与文档盘点，未修改两条路线的实现、依赖、资源或运行组合。

## 目标优先于现有分层

用户确认：自有枪械 Mod 自己完成枪械与配件的定义、兼容、组装、供弹、射击、瞄准、动作和显示闭环。TaCZ 融合版作为平级实现，同样自己完成闭环。公共物品、库存、角色、战斗通过有限边界服务它们；共享算法不是共享业务所有权。短期不加载另一套实现，未来内容分开，当前不做共存框架或跨引擎枪械存档转换。

这里的独立是无需另一枪械实现也能完成声明的功能，不等于必须零基础库依赖或把公共库存复制进来。独立开发用供弹替身不等于正式物品闭环已经完成。

## 自有实现的当前事实

主 NewMod `source/mods/firearms` 已有独立 FirearmItem、ActionSession、ServerFirearms、FirearmProtocol 和 FirearmShotEvent。Gradle 当前没有声明公共武器模块依赖，verifyIndependence 拒绝 TaCZ 类；普通运行代码也未见 dev.tacticaltacz/com.tacz 引用。

FirearmItem.feed 提供供弹，canOperate 提供可操作判断；服务端发出已扣弹射击事件。README 明确尚无正式模型、持枪渲染、弹丸和伤害实现，开发供弹是铁粒测试样本。这里仅核对源码，未重跑另一个 thread 的测试，不将其文档记录当成本轮验收。

## 主要冲突与处理建议

| 冲突 | 代码证据（相对 NewMod） | 目标归属与处理 |
| --- | --- | --- |
| 文档仍把装配规则视为外部公共责任 | firearms/README.md、docs/进行中/独立枪械最小工程盘点.md | 与最新目标冲突；在另一路实施前更新约定。本线程不修改其正在工作的文件 |
| 公共 weapon_runtime 不只是通用接口 | WeaponCapabilities 持有 AssemblyCatalog、criticalPaths 并读取 foundation AssemblyTrees | 开火就绪、关键件语义归枪械闭环；工具可复用，但不能强迫两条路线共用此 profile/树格式 |
| 两套装配验证叠在一起 | weapon_assembly AssemblyEngine；foundation AssemblyPlanner/AssemblyTrees 按 AssemblyDefinitions 校验槽位 | foundation 保留实例唯一性、深度、完整性等通用约束；枪械兼容与开火规则由闭环提供。逐项核对现有重复校验，不能简单删掉其中一层 |
| 配件物理状态与规则耦合 | adapter AssemblyGunExchange 先 ENGINE 校验再写 AssemblyComponents.STATE，随后投影对比 | 公共库存只原子提交枪械提供的合法变更与退还物品；闭环拥有拆装含义。可选择复用通用物品树，但不是对外必需的枪械格式 |
| 弹匣尚未形成完整物理状态 | AssemblyGunExchange 拆弹匣时将 TaCZ 枪身弹数退成散弹，膛内弹保留 | 不可原封不动作为自有物理弹匣合同；闭环明确弹匣余弹、膛内弹、换弹中间态唯一归属。此轮只列缺口 |
| 弹药内容在 fork，使用能力却靠 adapter | fork TarkovAmmoItem；adapter ContentAmmoMixin implements IAmmo、AmmoBridge | 资源保留，TaCZ 融合版吸收其使用逻辑。自有正式弹药尚未注册，不能依赖 fork 类；未来复用同一物品 ID 时必须明确唯一注册者，目前不删除或复制 |
| 组装界面同时依赖公共树与模型类型 | weapon_assembly_ui/build.gradle 依赖 foundation/weapon_assembly/weapon_models | 枪械的槽位显示与操作流程属于闭环；布局、拖拽、绘制工具可以复用，不要求两个实现共享完整编辑器或协议 |
| 模型数学存在隐性测试耦合 | weapon_models/build.gradle 测试输入读取 tacz_adapter 预设 | 纯数学可留作库；测试资源应独立保存。TaCZ 骨骼映射、姿态策略与配置解释归对应闭环 |
| 运行边界尚未统一但不宜强推状态机共享 | TaCZ LivingEntityShoot 等；firearms ActionSession/FirearmShotEvent | 各自维护动作、网络、预测和供弹状态；对外统一可操作结果/命中输入等必要语义，不把另一实现的状态机当公共前提 |
| 战斗与角色接入散在 adapter | TacticalTaczAdapter、BulletMixin、AimResourceMixin、ClientAimResourceMixin | TaCZ 内部直接衔接公共角色/战斗能力；自有独立实现同类衔接。两边确保一发只扣弹一次、一次命中只结算一次 |

## 最小对外边界

1. 物品/库存：识别实例、展示通用信息，原子扣取与返还物品；枪械提交合法变更，失败不留下半次安装。
2. 角色：向枪械提供动作许可和资源消耗结果；枪械反馈持枪/瞄准状态。许可检查应发生在开火/扣弹之前，不能依赖已扣弹且不可取消的 FirearmShotEvent 事后否决。
3. 战斗：枪械负责形成射击与命中上下文；公共战斗负责伤害/防护结算。具体事件类型可以不同，但责任和单次结算语义一致。
4. 界面：公共系统提供打开入口与基础交互；枪械解释配件树、槽位、兼容与编辑结果。

公共系统不认识 TaCZ 骨骼、firearms ActionSession 或某把枪的必需枪管路径。闭环可共用算法实现，不必将这些概念提升成全局业务注册表。

## 下一步与验证归宿

先将 adapter 的 36 个文件按“TaCZ 内部能力/公共边界连接/导入内容”归类迁入，保持 86 种弹药；同时确定公共基础模块的可复现引用方式。配件与开火规则按上述归属收回闭环，再以原生 M4A1 验证。先前融合盘点的 A/B/C 批次仅为草案，需按此文更新所有权后才能进入正式实施。

验证目标：单独构建/加载所选枪械实现；不存在另一实现的必需类；库存原子性和状态唯一性成立；模型/瞄准/换弹由自身配件数据驱动；公共战斗仅结算一次。当前未实施也未验收。

待明确的工程选择：公共工具的发布/源码引用方式，旧 adapter 命名空间兼容，未来弹药是否跨实现共用身份。它们不阻塞当前盘点，不以等待这些决定为由改动另一 thread。
