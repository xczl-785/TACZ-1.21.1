# 十枪交叉作者源与生成输出复核

日期：2026-09-17。此文是独立静态复核，不操作 Blockbench、不启动游戏，也不替代所有者实机验收。

## AI AWP / M700 / M870 / P90 / UZI 作者源

审阅范围是五枪的 `production.json`、`source-audit.json`、原枪 `data/index`、display、动画和几何元信息，以及共享生产器的配置前置校验。

- 每枪 source audit 的实际 cube 总数为 AWP 521、M700 353、M870 273、P90 300、UZI 333；均为零未归属、零重复。默认实体数分别为 7、6、7、7、10。
- AWP 与 M700 的枪机、枪管、枪托、机瞄和弹匣是明确实体；M700 的 `main_body` 三段 cube 切分已在审计中以固定来源索引留证，不能再按名称模式重排。M870 保留机匣、枪管、储弹管、机瞄、泵动护木、枪机与枪托；P90 保留机匣、枪管、默认枪口、释匣件、弹匣和拉机柄；UZI 保留机匣、折叠枪托、枪管、护木、握把、释匣件、拉机柄、枪机和弹匣。
- M870 为 `internal_tube`，使用 `feedPath=[tube]` 和 `capacityPaths=[tube,tube_extension]`，不具备 detachable magazine 路径；默认管与三个延长节都进入动态子弹门禁，保留原生逐发可中断装填语义。
- 五枪都声明了可执行的 `sightAlternatives`：既有光学候选路径和原生物理机瞄路径均为二维路径数组。AWP、M870 的枪托和 UZI 的弹匣没有再被错误设为射击必要件。
- 原生动态节点都有物理门禁：AWP/M700/UZI 的枪机与子弹、M870 的枪机/泵动/子弹、P90 的拉机柄。口径从 `GunAdoption` 读取，容量件只来自原生标签和几何变体，不由口径猜测。

`produce.validate_configuration` 已对上述五份配置通过；该检查覆盖真实口径、有效供弹路径、明确 LOD strategy、所有 `$` 槽位类型可由 nativeProfile 路由、库存类型和 footprint。

## QBZ-191 / SCAR-H / MK14 / SKS Tactical / AA-12 生成输出

在机瞄语义修正前，曾以独立 Python 进程逐枪运行 `tools/native_guns/validate.py`，验证生成输出与当时作者源、原枪 data/display/动画来源哈希、原生骨元信息、UV/图集、scene/catalog、动态门禁和实际资源路径一致。该轮资源须由主线程按新 profile 统一重生成后复跑，不能将旧输出对照作为新机瞄语义的完成证明。

复核期间发现并已修正四处作者源问题：QBZ-191、SCAR-H、MK14 的 `ar_stock_adapter` 由默认可替换枪托移回原生条件 presentation 叶；四把有枪托路径的枪显式引用共享 `stocks.json` 覆盖表；SCAR-H 导气组件加入机械必要门禁，瞄具安装座不再被误作开火必要件；五枪无光学机瞄不再只检查后照门，而是前、后准星（MK14 为枪管与后照门）同时存在。SKS 两个 OEM 枪托父骨保持可见，交给实体选择。AA-12 的 Duckbill 保留原 tag，并显式引用补充 editable/source library。

本复核仅证明源与生成资源的静态一致性和配置形状可加载性；不证明机瞄拆前/拆后语义、客户端动画观感、换弹手感、FPS、多人与存档。机瞄语义须在新输出生成后增加“拆前准星、拆后照门、完整机瞄、已装光学”四种配置测试，以上也仍属于后续构建和所有者实机验收。
