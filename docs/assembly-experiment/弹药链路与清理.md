# 弹药链路与本轮清理

2026-09-15，独立实验工程 `TACZ-1.21.1-experiments` / `experiment/standalone`。
本轮基线 `61ef39152c1cf7658a1f499c546c939455a2b284`。本文件是本次弹药清理与独立装填结论的当前入口；旧 `docs/newmod` 中的联合运行记录是历史证据。

## 结果与边界

保留全部 86 种塔科夫弹药及 12 个口径，旧物品 ID、输入、生成结果、模型、像素图、语言和参数不变。15 把枪使用 9 个原生口径标识，24 个原生弹药索引及其显示依赖完整保留。仅删除两张无引用的原生弹药栏位图片，共 4,835 字节。

**独立环境的普通生存装填目前不通。** 塔科夫弹药类没有实现 `IAmmo`；原生 `AmmoItem.isAmmoOfGun()` 固定返回 `false`。清理不解决这个既有缺口，也没有通过创造模式、虚拟弹药或直接写枪内弹数绕过它。

本轮不修改任何运行 Java、枪械数据、枪模、动画、Lua、组装模块、改装接口、Gradle 构建配置或 NewMod 主工程。未启动游戏和世界；实机验收由所有者执行。

## 六类东西不能混为一谈

| 类别 | 当前入口与用途 | 本轮处理 / 理由 |
| --- | --- | --- |
| 塔科夫物品 | `AmmunitionRegistry` 从 `ammunition/runtime/data/tarkov_content/catalog/ammunition.json` 注册 86 个 `TarkovAmmoItem`；`GunMod` 挂到 Mod 总线 | 全保留。ID 是 `tarkov_content:ammo_<sourceId>`，不是 `tacz:<口径>` |
| 原生物品入口 | `ModItems.AMMO` 注册一个 `tacz:ammo`，通过 `AmmoId` 区分口径；创造弹药栏为空但图标仍由 builder 创建；旧物品和 `/give` 仍能引用 | 保留注册、builder、数据访问器与渲染。生存 `dropAllAmmo` 仍生成这种物品；直接删除会改变存档/退弹语义 |
| 原生口径索引 | `data/tacz/index/ammo/*.json` 共 24 份，包含名称、display、stack_size、sort；枪 data 的 `ammo` 指向它 | 保留全部。它不是 24 个注册物品，也不是塔科夫伤害参数表；CommonAmmoIndex 还为旧物品栈大小和退弹分堆服务 |
| 显示资源 | `display/ammo` 的 item model/texture/slot/transform 供旧物品渲染；name 供名称；索引必须能找到 display | 保留被引用的全部资源。`ClientAmmoIndex.loadModelsIfNecessary` 先装物品模型，再装 entity/shell，不能留下损坏物品模型引用 |
| 弹壳与射击效果 | display 的 `shell`、`entity`、`particle`、`tracer_color`；shell 模型/贴图及 `_n`/`_s` 伴随贴图 | 全保留。抛壳直接沿枪的原生 ammo ID 查索引；弹丸渲染、弹孔和粒子也读这个索引，不等同于物品入口 |
| 无引用图片 | `textures/ammo/slot/20x82.png`、`textures/ammo/slot/font.png` | 可安全删除并已删除：24 份 display、生产 Java/JSON/Lua 中均无资源地址引用，也不是被用贴图的 shader 伴随文件 |

原生弹药配方已在此前工作台清理中删除，`SelectedContentPolicy` 仍屏蔽 `recipe/ammo/*.json` 的旧包回流，本轮不重复计算为新删除。`IAmmo`、`IAmmoBox` 是接口，不能因为内置原生弹药退役就删掉寻弹扩展契约。

24 个索引中，不被现有 15 枪直接使用的索引也没有被当作“安全垃圾”：其中 357mag/50ae/50bmg 是保留塔科夫弹药的既有显示映射；其他索引仍是已加载的旧物品显示、旧 ID 和历史效果资源。删它们需要另行收回入口及兼容语义，不属于本次两张孤立图片的删除依据。

## 独立环境装填：实际代码路径

1. `LocalPlayerReload.reload()` 检查主手、状态及 `canReload`。生存玩家未通过时，客户端不会发换弹包。
2. `ClientMessagePlayerReloadGun.handle()` 转给 `IGunOperator.reload()` → `LivingEntityReload.reload()`；服务端再检查冷却/动作/供弹并触发可取消的换弹事件。
3. `AbstractGunItem.canReload()` 在普通实物供弹时扫描实体的 `Capabilities.ItemHandler.ENTITY`，要求物品实现 `IAmmo` 并通过 `isAmmoOfGun`（或通过 `IAmmoBox`）。它不直接读 NewMod 胸挂/口袋。
4. 独立工程的 `TarkovAmmoItem extends Item`，没有 `IAmmo`；原生 `AmmoItem` 虽有接口，匹配恒为 false。故正常生存玩家持 86 种塔科夫弹药不能触发实物装填。
5. 对能进入装填流程的情形，`ModernKineticGunItem` 或配置的 Lua 在供弹时刻调用 `ModernKineticGunScriptAPI.consumeAmmoFromPlayer()` → `findAndExtractInventoryAmmo()`。后者再次按 `IAmmo`/`IAmmoBox` 匹配并实际扣取，不是播放动画就增加正确弹种。
6. 创造玩家的 `LivingEntityAmmoCheck.needCheckAmmo()` 为 false，默认/Lua 换弹可以直接填充计数；虚拟备弹 `DummyAmmo`、已有枪内弹数也是另一路。它们都不能证明塔科夫实物装填可用。15 枪的 reload 配置均未开启 infinite。
7. 既有枪内状态只有计数/膛内状态不代表拥有正确塔科夫弹种。原生 `dropAllAmmo()` 对正常生存退弹按 gunData.ammo 经 `AmmoItemBuilder` 生成 `tacz:ammo`，不退膛内弹。因此本轮保留该物品注册与索引，不用删除注册来掩盖错误弹种风险。

NewMod 的外部 adapter 中，`ContentAmmoMixin` 补 `IAmmo` 与口径映射；`ReloadMixin` 补 `canReload`/退弹；`ScriptAmmoMixin` 补消费、弹种和初速/弹丸数等；`AmmoBridge` 处理实际库存与弹种状态。独立工程 build 和 mixin 配置没有安装这些连接。仅把 `IAmmo` 加到 86 个物品上，仍不能保证单一弹种、正确退还、公共库存一致及命中结算，因此本轮不做这种局部替代。后续归属见本文件“后续独立供弹”。
