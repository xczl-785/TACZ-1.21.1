## 完整目标与当前事实

TaCZ 实验室以原生枪械完成真实配件、组装、库存、持久化、同步、外观、属性、开火限制及原生动作的完整链路。未来自有 firearms 接替枪械运行，组装规则、定位、界面和公共玩法接入可迁移。当前四个 weapon 独立 Mod 与 adapter 分散承载能力；原生 M4A1 仅有离线几何拆分，未成为游戏内组装枪。

最终一个 tacz Mod 承载四个 weapon 的内部模块和 adapter 专属职责。foundation、tactical、character、combat 继续独立；不迁入通用物品、库存、人物与伤害规则。不建立双引擎切换框架，不修改 firearms。

本文覆盖旧 README 中 A/B/C 的批次顺序及“weapon 保持独立 Mod”的建议；旧盘点保留作事实和迁移证据，不作为当前实施授权。

## 第一项实施合同

### 可修改范围

- 实验室仓库为主要实施位置。把 weapon_assembly、weapon_models、weapon_runtime、weapon_assembly_ui 收入 tacz；可保留普通 Java 子工程，但只发布/加载一个 tacz Mod，不保留四套 @Mod 与 Mod 元数据。
- 允许修改 NewMod 中必要的 settings/build、依赖元数据、adapter 消费入口、运行配置、资源/边界校验、vendor 制品及 dependency-lock，以形成真实可验收组合。
- 四个模块从 NewMod 迁出后不得留下另一份有效生产源码或重复类；旧路径消费者、测试夹具和脚本引用一起迁移。允许保留明确的历史资料，不能保留双份运行事实源。
- adapter 仍是独立 Mod；其组装、供弹、战斗等实现及三枪内容不在本项吸收。仅做消费新包所必需的调整。

### 必须保护

- 组装算法独立于 TaCZ 与 Minecraft，保留纯 JDK 编译验证；几何数学不依赖 TaCZ 具体渲染器；客户端 UI 不进入服务端类加载路径。
- 真实配件状态继续归 foundation，扣除返还继续调用 tactical；不建立第二套物品状态。
- 保留已有组件和资源身份，尤其 weapon_runtime:profile；撤销 Mod 入口不等于改资源命名空间。
- 不做枪械拆分、配件内容扩充、三枪退役或 firearms 修改；不改变供退弹语义。固定口径退弹临时接口及其缺口归后续，不因此增加退弹键。
- 15 枪、85 配件、86 弹的现有保留范围及抛壳等效果继续保护；许可与来源记录随迁移保留。

### 为什么允许暂留 adapter

第一项完成时运行组合为“tacz（含四个 weapon）+ adapter + 公共玩法 Mod”。adapter 暂留是为了让本次只验证模块合并且维持完整验收入口。第二项接受后删除其独立加载边界；不以当前过渡形态建设长期新接口。
