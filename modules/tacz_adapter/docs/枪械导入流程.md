# 枪械模型与真实武器导入流程

供接手新枪的 agent 使用。目标是将用户交付的模型接成有真实物品身份、正式名称、预设、材质、工作台和射击执行的武器，并留下可重建资源。材质只维护一份[补充说明](../../weapon_assembly_ui/材质使用说明.md)。当前实例：[M4A1 标准版](../weapon-sources/m4a1/README.md)、[ADAR](../../../../NewMod/docs/参考资料/adar-20260913-data/武器接入说明.md)、[雷电 Model 1](../weapon-sources/radian/README.md)。

当前第一人称作者合同见[握持、瞄准与射击反馈](握持瞄准与射击反馈方案.md)。每个作者目录必须提供 `markers.json` 和 `handling.json`；两类素材生成入口统一调用 `build_presentation.py`，不再用固定 iron_view/手角度作为最终校准。

## 通用路径与职责

运行逻辑位于 `src/main/java/dev/tacticaltacz/assembled/`，按配置支持任意数量的已注册枪械，不包含按 ADAR/Radian 名称分支的注册、领取、工作台或持枪代码。

- `AssembledWeapons` 读取 `data/tactical_tacz_adapter/assembled_weapons.json` 的注册列表，创建每个 `AssembledWeapon`；注册项数不固定。
- `AssembledWeapon` 读取每枪 `weapon.json`、型号目录、物品映射和预设，创建新的实例身份，将真实装配组件投影给算法。
- `AssemblyGunItem` 创建该枪完整预设；`AssemblyGunModel` 按配置读取网格、材质、比例和可选准星。顶点/法线按资源加载预计算，同型号多个实例按各自路径显示。
- `AssemblyGunClient/Protocol/Workbench/Exchange` 共用工作台、服务端快照和库存事务；根据当前枪的目录与弹匣路径处理操作。
- `GunAdoption` 自动采用配置口径，开发目录自动列出配置来源与正式物品。新增同类枪不改这些 Java 类。

`weapon_assembly` 管兼容算法；`weapon_models` 管共享几何和材质合同；foundation 管装配组件与身份；tactical 管权威库存；`weapon_runtime` 管开火条件；`tacz_adapter` 对接 TaCZ。UI 只消费宿主视图，不持有库存权威事实。

当前执行策略为 `detachable_magazine`，即 TaCZ 持有余弹与膛内弹、实体弹匣为结构件；弹匣路径可配置，拆下其所在子树也安全退回余弹。新的内置弹仓、带弹实体弹匣、特殊动画或光学能力需要扩展相应策略，不能套用现有行为；未知供弹策略会拒绝加载。跨枪共同物品目录尚未合并，重复注册相同物品 ID 会明确报错，不自动覆盖。这些是能力边界，不是枪械数量限制。

## 1. 接收正确素材

先读项目指令、`git status` 与批次 README，分清其他任务改动。保留只读原稿和哈希；使用供消费的组件修订，不在归档上加工。Blockbench MCP 是检查工具，玩家运行不依赖它。

对本批确认：完整预设、每件型号 ID、父件与槽位、模型/变体、坐标空间、内部变换、材质和 UV。保留隐藏网格与互斥状态，不能把所有 LOD 或折叠/展开机瞄叠在一起。雷电使用 `original-components/4.1.3/radian-original-20260914-r2`；r1 存在 mesh.origin 重复位移，禁止作为输入。

材料选择：已带材质则保留原纹理与 UV；只有白模则制作原创纹理和分区。两种都进入同一运行时材质合同，详见材质补充说明。

## 2. 预设和正式名称

在 `modules/tacz_adapter/weapon-sources/<枪械>/` 保存：

| 文件 | 内容 |
| --- | --- |
| `source-pack/` | 只读组件、安装矩阵、批次清单与来源报告 |
| `preset.source.json` | 原始预设 ID、实例/型号、父件和槽位 |
| `items.raw.json` | EFTForge 选定型号完整原始记录，保留完整兼容/冲突清单 |
| `names.json` | 按物品 ID 保存正式 `zh`、`en` 名称，保留数据原文 |
| `source.json` | 源路径、版本、修订及所有输入 SHA-256 |
| 生成报告 | 不放在原始资料目录。通过 `--reports` 写入独立目录；历史报告在模块 `weapon-reports/archive/` |

数据优先使用用户交付预设，并与本地 `EFTForge/docs/data/cache/items.json` 核对；正式名称来自相邻 `items_zh.json` 与 `items_en.json`，不要从 normalizedName 拼词或将模型文件的简写当展示名。缺名称时先找来源，不自行编造“正式名称”。保留 `mod_reciever` 等源槽位拼写。

每条父子边必须在源允许清单内，同时满足排除、冲突和预设必需件。原始清单不裁剪；本批运行目录可以限定为有模型的候选，并记录范围。EFTForge 不提供模型安装坐标；安装矩阵由素材提供。

## 3. 为新枪配置资源

在 `modules/tacz_adapter/weapon-authoring/<枪械>/` 新建自己的配置。使用现有实例理解字段，不覆盖其路径、型号或参数。

| 配置 | 职责 |
| --- | --- |
| `runtime.json` | gunId、根型号、资源目录、modelType、可选旧 itemType、口径、开发来源、供弹策略、弹匣路径、开火必需路径、默认模式、meshScale、可选准星 |
| `import.json` | 源数据目录、共同坐标根挂点、容量/开火模式/RPM、物品格数、可动骨骼归属、枪口坐标、分类标签、可选材质分区规则 |
| `library.json` | 材质颜色、PNG、粗糙度、反光强度、纹理比例 |
| `materials.json` | 每件默认材质与区域覆盖 |
| `presentation.json` | 普通/瞄准相机、枪模 FOV、双手枢轴/渲染节点/角度 |
| `execution.json` | TaCZ 射击、装填与手感配置；区分源事实与演示参数 |
| `animations.json` | 枪械的骨骼动作，不能机械套用不匹配的装填结构 |
| `display.json` | TaCZ 视角、第三人称、声效和枪口效果；资源 ID 由生成器写入本枪命名空间 |

所有真实物品都必须有注册、尺寸/重量、分类身份和装配声明。分类必须引用已有标签；不要为能放进背包而放宽库存规则。新的物品 ID、枪械 ID、modelType、itemType 不能与已注册项冲突。

## 4. 转换和生成

目前 `tools/build_weapon.py` 支持**已烘焙内部变换的三角自由网格组件**：平铺网格或单层零变换组、零 mesh.origin、每件完整 `local_to_assembly` 矩阵。矩阵的旋转/缩放/镜像一起应用，镜像反转绕序；保留原面 UV 并按源纹理分辨率归一化。内部非零变换、未三角化面、嵌套组和无法表达的分类过滤会明确拒绝，不静默丢弃。

转换为 `ModelGeometry` schema 3：顶点 = 完整矩阵 × 源局部顶点 − 本件挂点；父槽 = 子件挂点 − 父件挂点。沿树重装恢复原整枪相对坐标；动画枢轴与安装挂点分别维护。`regionRules` 可按共同坐标范围拆出尾垫等材质区，只改变区域，不改几何或 UV。

在 **TaCZ 实验室根目录** 执行三枪完整重建（每次换用空输出目录）：

```sh
python3 modules/tacz_adapter/tools/weapon_pipeline.py all \
  --output /tmp/newmod-weapons-review/resources \
  --reports /tmp/newmod-weapons-review/reports \
  --compare modules/tacz_adapter/weapon-content/resources
```

统一入口按 `import.json.converter` 选择 `matrix-components` 或 `legacy-adar`，共用注册索引、第一人称生成、图标和资源验证。`all` 自动发现所有作者目录；也可填单枪目录名，单枪输出索引只含该枪。输出必须是空目录，报告必须放在另一目录，不允许直接写生产/输入目录。生成前后计算来源与配置哈希，报告保存输入指纹及完整资源引用归属（`references.json`）。枪械材质必须全部出现在当前生成目录；检查器和离线预览不借用 UI 或旧目录的纹理。比较 JSON 的完整数据与数组顺序、PNG 的 RGBA 像素，语义变化返回失败并逐文件列出；仅排版差异另列。新增枪首次对比会出现新增文件，这是待审查的预期差异，不能跳过审查。

组件局部白模批次先用 `prepare_local_components.py` 将预设、同版 SPT 数据与显式安装配置转换成相同快照合同，见 M4A1 作者目录的 `placement.json`。它根据父源根与节点计算安装关系，不把 `local_to_source_baked` 当作整枪矩阵；安装修正须有该批证据，不能由版本号猜测。原产出白模保持原样，派生元数据另存。

`import.json.textureInputs` 可按材质键指定快照内PNG路径和SHA-256，生成器保留原UV、最近邻生成256×256运行图，颜色只在材质库乘一次；未配置图片输入时维持原来的确定性纹理生成。共享纹理可使用共同资源命名空间，避免每件复制，但文件仍必须由当前内容生成并打包。M4A1 的 `firearm_materials` 就在 `weapon-content/resources/assets/firearm_materials/`；所有被材质库引用的共享纹理也参与语义对比。ADAR 使用 `import.json.textureCopies` 声明目标资源 ID、来源快照路径和 SHA-256，按原始字节复制纹理到 `newmod_adar`，不改变像素。

旧 ADAR 白模的来源结构不同，生产来源已迁到 `weapon-sources/adar/`，通过 `tools/build_adar.py` 转换；UI 导入器仅保留历史开发用途，不再是生产步骤；它的**运行逻辑已迁入同一个 assembled 实现**。旧源转换器不是新枪模板。ADAR 的旧骨架由作者目录 `rig.json` 保留，执行/动画/显示分别在 `execution.json`、`animations.json`、`display.json`，身份分类在 `identities.json`、历史文案在 `lang/`；本批没有重调数值。ADAR 物品 ID、装配组件格式、实例身份字段和已存在的协议 wire ID 保持不变，不做存档替换。

Python 需要 Pillow、NumPy。不要用 `-O` 运行依赖 assert 的旧脚本。Java 使用工程 Java 21 和 Gradle wrapper；公共编译依赖以 `public-dependency-lock.json` 和 `verifyGameplayDependencies` 为配置事实；NewMod 验收制品以宿主锁为准。


## 目录与更新生产内容

| 位置 | 谁维护、何时修改 |
| --- | --- |
| `weapon-sources/` 及 `import.json.source` 指向的原始资料 | 来源与已接受快照，只读；替换素材须保留旧版和来源记录 |
| `weapon-authoring/<枪>/` | 人工配置；新枪在此准备 `import/runtime/library/materials/presentation/execution/animations/display/handling/markers`，局部组件来源还需要 `placement.json` |
| `weapon-content/resources/` | 生成物；与 adapter 同包，Jar 内 ID 和资源路径不变 |
| `--reports` 目录 | 每枪转换报告、来源和作者配置哈希、资源语义差异；本次证据归档到 `weapon-reports/refactor-20260915/` |
| `src/main/java`、`src/main/resources` | 通用 TaCZ 接入及其配置，不放逐枪制作资料 |

完成隔离生成和差异审查后，用**完整 all 产物**更新专用生产内容目录：

```sh
rsync -a --delete /tmp/newmod-weapons-review/resources/ modules/tacz_adapter/weapon-content/resources/
python3 modules/tacz_adapter/tools/validate_weapon_resources.py
./source/gradlew -p source :tacz_adapter:compileJava :tacz_adapter:compileDevelopmentJava :tacz_adapter:processResources :tacz_adapter:verifyAdarIconRenderer
```

更新前核对 `git status`，确认目标没有其他任务修改。`--delete` 仅用于这里专属的生成目录，不能用于模块目录或 `src/main/resources`。重新生成会覆盖手改内容，因此所有意图必须落在配置/来源里。

新增同类枪无需修改 `AssembledWeapons`、`AssembledWeapon`、`AssemblyGunItem/Model/Workbench/Exchange/Protocol`，也无需新增 Mod 或改 Gradle。准备完整来源和作者配置后由 `all` 发现。当前每枪独占 namespace；重复 gunId、modelType、itemType 或物品 ID 拒绝构建/注册。注册在启动时完成，不支持随放随用或热注册。不同供弹策略、原生 Bedrock 骨骼来源、跨枪共享同一物品 ID 应另开有明确合同的扩展工作。

## 5. 外观校准

先按模型光轴配置普通相机与 ADS，再分别校准双手接触点、手臂渲染节点和第三人称。仅 ADS 显小先调相机距离/枪模 FOV，不同时缩放整枪。骨架生成和运行网格须使用同一 meshScale；更换护木/前握把后重查接触点。

独立配件图标使用同一几何/UV/材质生成，不交付统一灰色剪影。当前整枪图标仍为固定根件示意；未来当前装配状态预览接口接管，不把固定完整枪图当最终动态方案。可选准星由配置提供；雷电默认使用实体展开机瞄，不生成虚假红点。

## 6. 编译与验收分开

```sh
./source/gradlew -p source assemble :tacz_adapter:compileDevelopmentJava verifyModuleBoundaries verifyLocalization verifyDistribution
```

`processResources` 自动执行 `verifyConfiguredWeapons`，检查所有已配置枪械的注册冲突、预设/物品/分类/几何/材质/贴图/双语名称和 TaCZ 资源引用。编译不需要外部盘、Blockbench 或开启世界；所有运行资源随 Jar 打包。

按用户要求决定是否运行游戏测试。**2026-09-14 雷电本批用户明确只要求编译，实机验收由用户做；本次没有运行服务端 smoke 或客户端 audit。** 仅用静态预览确认配色，不冒充游戏截图。

用户验收入口：启动根目录 `启动开发客户端.command`，`/devitems` 按配置来源筛选（雷电为 `radian`），领取完整预设与配件。主武器槽切换持枪，Z 打开同一个真实组装工作台。配件正式名称随游戏语言切换。

实机关注：领取/存放、逐件拆装与子树/身份守恒、缺件禁射、容量与扣弹、拆匣退弹/膛内弹、保存重进、实际射击、双手接触点、机瞄对齐、换弹/第三人称及中英文界面。编译成功不能证明以上操作通过。

既有 `runAdapterSmoke`、`runAdarAudit` 保留为工程入口；ADAR 组装分支还需 `JAVA_TOOL_OPTIONS=-Dnewmod.adarAssemblyAudit=true`。它们的历史成功不代表新枪或本次共享逻辑已实机验证。不得用日常 `source/runs/tactical-client` 做自动清理/重建测试。

交付保留用户反馈和未完成项的明确归属。写 RouteLedger 前重新核对 runtime 与 current version；本项目当前工具期望 `expectedRouteLedgerRoot` 为 NewMod 根，实际 JSON 在 `.routeledger/`，不能混淆。雷电 Todo：`b11c3ae7-d1a6-4a05-aa9c-57ab96359286`，待用户验收，不因编译成功关闭。

## 反向验证所得

ADAR 重建曾证明逐字节一致，见其批次说明。雷电接入实际暴露并补齐：来源修订与完整矩阵、保留原 UV、原版名称、动态注册、可配置供弹路径和可选准星、不同枪切换工作台刷新、较大网格预计算、材质/身份/引用编译期检查。本文现在描述当前实现的通用结构，不再要求新增枪时复制 AdarContent/AdarGunModel/工作台类。
