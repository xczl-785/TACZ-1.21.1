## 采用的边界

完整目标是一份可追溯来源和人工配置，经来源转换、共同生成与检查，得到可打包的枪械内容；通用组装算法和 TaCZ 接入各有自己的责任。当前三枪是这个目标的实际内容，不为整理另建 Mod，不复制每枪 Java。

- `weapon-sources/` 统一说明三枪来源。ADAR 的已接受派生几何和纹理独立快照在这里；雷电、M4A1 通过各自 `import.json` 引用原来的完整来源目录，不移动/裁剪原稿。所有来源保留记录。
- `weapon-authoring/<枪>/` 是人工修改入口。ADAR 的材质、旧界面文案、身份分类、显示、运行参数、动画和旧骨架已从 UI/工具或原先人工维护的运行资源中归拢到这里。
- `weapon-content/resources/` 是专属生成内容目录。175 个运行资源仅迁移磁盘位置，现有文件逐字节不变；打包后的路径、资源 ID、注册方式不变。
- `src/main/java/dev/tacticaltacz/assembled/` 继续负责共同的注册、物品、TaCZ 绘制与执行衔接；没有修改 Java。`src/main/resources/` 保留接入元数据和公共配置。
- `weapon_pipeline.py` 是统一入口：选择来源转换器 → 生成网格/物品/材质 → 共用图标和第一人称生成 → 共同注册索引 → 资源检查 → 可选语义比较。报告只写独立 `--reports` 目录。

保留 ADAR 旧来源转换器，是因为它消费已经接受的 catalog/scene/manifest；矩阵来源转换器消费 source-pack/安装矩阵。强行重算 ADAR 原始几何会扩大几何变更风险。本次不造没有第二个实际消费者的中间框架，两者已有相同运行输出和共同后续阶段。
