# Z改装与战术库存

状态：当前实现合同；2026-09-13所有者选定。工程证据见[验证记录](refit-verification.json)，本批所有者实机接受单独记录，自动成功不等于接受。

## 玩家规则

Z沿用TaCZ界面及枪械/配件兼容判定。服务器列出随身直接可用的口袋、胸挂、背包、安全箱配件；客户端再按当前枪械、选中类型筛选。仓库、外部搜刮容器、未穿戴的嵌套容器不参与。配件没有项目资料也可使用，遵守[未接入物品兜底](../../../../NewMod/source/mods/foundation/docs/未接入物品兜底.md)。

- 安装消耗所选真实堆叠中的1件；替换先尝试把旧配件放回腾出的原格，不能放回则走普通随身入库顺序。
- 拆卸须有空间接收；没有空间整笔拒绝，枪、配件和弹量不变。返还不调用拾取入口、不自动装备、不溢出到仓库或地面。
- 更换/拆卸扩容配件仍退掉枪内弹匣计数所代表的弹药，保留枪膛和所选弹种。原弹种12发就返还该弹种12发，和旧配件一起检查空间；旧档有弹量却无受支持弹种身份时拒绝该次退弹改装，不能编造替代弹。
- 必须持有合法租约中的已接入枪械；装填、拉栓、切枪冷却、射击冷却、使用物品或预约事务进行中不改装。锁定枪械仍拒绝。忙碌时界面会重新请求目录。
- 目录是当次服务器快照；物品移动、换枪、射击改变枪状态或重复点击后，旧请求拒绝并刷新，不能用旧槽号扣除另一件物品。
- 动画/枪械展示和安装拆卸音效沿用TaCZ；音效在成功回复后播放。不引入实体弹匣、混装或新的配件兼容机制，不补查看属性/重量。

## 职责与迁移位置

| 所有者 | 入口 | 职责 |
| --- | --- | --- |
| fork | `RefitInventoryExtension`、`GunRefitScreen` | 提供可选库存扩展、真实堆叠按钮；接管时拒绝旧原版槽号安装/拆卸包，无适配器保持原版库存流程 |
| tacz_adapter | `refit/RefitBridge`、`RefitProtocol`、`RefitClient` | 服务器目录及一次性令牌、兼容/忙碌/锁校验、在枪副本上修改原生配件和弹量；客户端只提交意图 |
| tactical | `api/TacticalHeldExchange` | 查询副本，校验租约/版本/组件/数量预约；一次规划扣除、返还与主手更新，统一持久化及同步 |
| foundation | 既有布局、容器准入、组件与事务校验 | 1×1兜底等物品规则；不依赖TaCZ |

枪在租约期间只由原生主手槽持有真实ItemStack；战术装备槽不复制枪。事务回调仅取得副本，不能直接写玩家或发布副作用；成功提交之后才刷新TaCZ属性。主手与库存写入在同一服务器线程连续执行，中间没有扩展回调。崩溃/断电级持久化与全项目多人可靠性仍按既有延期范围，不从本次测试推导完成。

自研枪械时复用`TacticalHeldExchange`，替换adapter的兼容和副本变换逻辑；tactical 的库存规则继续由公共 Mod 拥有，TaCZ 通过公共锁引用其 API，不嵌入其类，也不为 Z 复制另一套库存。枪体资料补齐导致尺寸变化时，需要扩展主手占格变更事务；当前共用入口明确拒绝主手物品种类/数量/尺寸改变。

## 验证与继续工作

当前实验室可执行 `bash gradlew adapterTest --offline` 做适配器专项；旧 `:tacz_adapter:runAdapterSmoke` / `runClientSmoke` 为独立模块时期命令，不再在本仓库执行。以下是该历史批次的验证记录。服务端覆盖真实事务和协议编解码，客户端常规smoke覆盖加载和既有页面，不能据此宣称实际Z点击已验收。尝试的隔离世界自动Z测试停在备份确认页，没有进入改装操作；所有者随后明确实机由本人测试，未把未完成的自动点击任务加入工程门槛。日常世界未改写。

所有者实机：领取兼容瞄具放口袋或背包，持枪打开Z，安装、替换、拆卸；再测试满空间拒绝，扩容配件退弹及枪膛保留。重启客户端才会使用新Jar。
