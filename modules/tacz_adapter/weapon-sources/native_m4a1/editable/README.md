# 原生 M4A1 默认配件编辑入口

本目录 `components/<definitionId>/model.bbmodel` 是 15 件默认配件的编辑源，每件都是居中的独立方块模型；`texture.png` 是该件的纹理来源。工作台、图标、原生持枪高模和低模由同一次生成更新，不手改生成物。

## 使用

1. 在 Blockbench 打开对应配件的 `model.bbmodel`，编辑方块外形或逐面 UV；保存模型。绘制纹理后也保存同目录 `texture.png`。PNG 为导入时的纹理权威来源，模型内嵌图仅用于编辑器打开预览。
2. 在实验室根运行 `PYTHONDONTWRITEBYTECODE=1 python3 tools/native_m4a1/generate.py`。生成器保留原生动作骨骼、安装树、物品身份和其他候选配件，替换此默认套件的几何。低模从当前每个源骨骼挑选最多两个大方块；高低模共用按相同 PNG 去重的纹理图集。
3. 执行 `python3 tools/native_m4a1/test_editable.py`、Gradle `check assemble`，审查资源差异，更新 NewMod 正式/开发 Jar 与依赖锁。Minecraft 验收由用户执行。
4. 查看整枪/拆解图：`python3 tools/native_m4a1/compose_editable.py --output <独立查看目录>`。总览是生成的查看副本，修改不会回写配件源。

每件的 `editorCenter` 恢复原安装坐标；组名前缀及内部骨骼关系用于映射原生动画。允许在现有骨骼组内增删、移动、旋转和缩放方块；不要改变骨骼名、父子关系、骨骼枢轴或旋转。此类改动需要连同动作重绑另行处理，生成器会明确拒绝。

保留默认机械瞄具，不扩展额外瞄准镜。本批编辑展开的前准星；折叠形态仍是原资源，后续编辑前准星时须一并评估折叠形态。其他候选的旧网格导出路径仍保留，其 UV 尺寸问题待进入对应候选批次修正。

## 来源与验证

来自原生高模的 14 件、原生 CTR 附件 1 件，共 583 个方块。`manifest.json` 保存原文件哈希、逐骨骼方块索引、安装位置和基线编辑源哈希。原生文件不修改；沿用 TaCZ 原版权/许可证。

M4 UV 为 256×256、PNG 为 512×512；CTR UV 为 64×64、PNG 为 128×128。导入按 UV 单位归一化，不能用 PNG 尺寸直接替代 UV 尺寸。

`blockbench-check.json` 记录 15 件独立加载/编译的方块坐标和 UV 往返检查。`../editable-import-report.json` 是当前生成输入及产物计数；测试核对工作台与原生高模的顶点位置、归一化 UV 及图集像素。未修改的基线配件还与原生源逐方块对照；已编辑配件不要求与旧形状相等。

CTR 在本枪的原生 rig 内按真实配件身份显示，避免改动其他枪共用的原始 CTR。更换成备用枪托时仍走原生附件渲染，不能重复显示两份枪托。
