# 枪械组装台完整方案

本文从最终用户体验倒推组装台的完整边界。它描述生产游戏内组装台；外置浏览器检查工具只是诊断入口，不是第二套组装实现。

## 完整目标

玩家打开组装台时，当前枪械、槽位和配件状态必须在第一张可见画面中一次就位。旋转枪械时，模型、挂点、连线和槽位使用同一相机帧；可以因边界或碰撞暂时保持位置，但不允许缓慢追赶或在多个避让位置间折返。配件预览可随时取消，只有服务端验证和库存交换成功后才能改变真实枪械。

## 一条完整链路

```text
打开请求
  → 服务端报价当前枪械、装配树和候选库存
  → WorkbenchAccess 提供只读视图与操作回调
  → WorkbenchScreen 同步控件、槽位和候选面板
  → AssemblyViewport 用同一相机帧绘制枪械并投影挂点
  → SlotLayout 在屏幕空间内生成可点击、不重叠的槽位位置
  → 悬停候选仅生成临时预览
  → 点击安装/拆卸发送服务端事务
  → AssemblyEngine 校验兼容、必需件和完整性
  → 库存原子交换成功后返回新报价
  → 界面以服务端结果重建可见状态
```

## 权威与模块边界

| 责任 | 唯一所有者 | 不得承担 |
| --- | --- | --- |
| 配件兼容、安装、替换、拆卸和完整性 | `weapon_assembly` / `AssemblyEngine` | UI 不复制规则 |
| 当前装配树和配件实例身份 | foundation 状态与服务端报价 | TaCZ 附件投影不得另存一份权威状态 |
| 库存扣除、返还和防重放 | tactical 库存与服务端会话 | 客户端预览不乐观写库存 |
| 模型几何、槽位挂点和附件原点 | `weapon_models` / `ModelGeometry` | 几何不决定兼容性 |
| 原生骨骼、材质、动画和光学效果 | TaCZ 原生渲染后端 | 组装 UI 不伪造另一套骨骼状态机 |
| 屏幕槽位位置与交互稳定性 | `weapon_assembly_ui` / `SlotLayout.State` | 渲染后端不保存 UI 位置 |

## 视口与槽位合同

- 开启：先构建完整 UI，再做 LDLib2 首次布局；第一张可见画面不允许暴露零位置控件。
- 单帧：`AssemblyViewport.beginFrame()`冻结相机快照，枪械、挂点、连线和卡片共用它。
- 无障碍跟随：卡片立即采用当前挂点位移，无速度积分、缓动或延迟队列。
- 密集碰撞：冲突组保持上一帧合法位置，其他卡片继续即时跟随；不在拖动期间寻找遥远临时空位。
- 交互边界：鼠标释放、相机复位或真实装配树改变时，只允许一次确定性整体重排；重排后当帧稳定。
- 安全性：卡片始终在可点击区域内且互不重叠；临时无效投影不覆盖上一张可用布局。
- 候选面板：依附选中卡片，与卡片共用当前位置，不另存跟随动画。

## 证据边界

纯 JVM 测试能证明布局确定性、边界、重叠、折返和会话规则；构建能证明代码、资源和模块边界。它们不能证明 Minecraft 实机手感、真实帧率、原生材质/光学效果或所有角度的主观可辨认性。最终客户端接受始终由所有者完成。
