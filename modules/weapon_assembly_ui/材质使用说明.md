# 枪械材质导入与制作

> 旧三枪材质作者链参考（`deprecated-asset`）：下文 ADAR、matrix-components 和旧 import 工具针对已经退役的生产链。保留 UV/材质来源经验，旧命令不作为当前制作步骤；当前源与制作入口见[十五枪作者源](../tacz_adapter/weapon-sources/README.md)。


本页是[枪械导入流程](../tacz_adapter/docs/枪械导入流程.md)的唯一材质补充说明，覆盖“已带材质”与“只有白模”两种交付。运行时使用统一材质库与区域绑定。新矩阵组件使用通用配置生成器，ADAR 保留旧源格式的外观编辑入口；两者都不能覆盖原稿。

## 先按素材选择分支

**交付已带材质：**保留交付的纹理与原 UV，核对每个面所用的贴图、尺寸、颜色、透明方式及文件来源。将贴图导出为运行资源中的 PNG，记录来源和哈希，映射到材质库与区域绑定；已有彩色纹理通常设置白色 `baseColor`，避免重复染色。Blockbench 预览图不等于完整材质输入，要检查实际面 UV 和图片引用。

当前 `import_adar.py` 会重新投影 UV，`generate_materials.py` 会生成原创纹理，**两者都不是保留交付材质的导入入口**。`import_material_project.py` 只接受本项目导出的带固定面/顶点身份的创作工程，并且不提取内嵌图片；任意新 `.bbmodel` 不能直接交给它。带材质新枪需要适配转换器，读取逐面纹理索引、以对应纹理 UV 宽高归一化坐标、保留原区域，并单独导出图片；用 Blockbench 与客户端对照确认后再接受生成结果。此分支尚未经过第二把枪验证，不能把本文当作现成的一键工具。

**只有白模：**保留原几何，在工作副本中划分木材、金属、橡胶等具名区域，创建原创基础材质和 UV。ADAR 已完成这一路径，可复用材质库和图标渲染器；每枪的分区、挂点与输出目录仍需适配。当前支持不透明基础色/贴图及简单高光；需要透明玻璃、完整 PBR 或其他效果时单列缺口，不默默丢弃材质通道。

两种分支最后都生成运行时几何 UV、材质库、零件/区域绑定和实际 PNG，再生成武器资源与配件图标。验收时同时看工作台、手持枪和独立配件；三条显示路径须读取同一外观数据。发布后的运行资源不依赖 Blockbench 或用户外部素材目录。

## ADAR 当前实例

当前 ADAR 默认显示原创简易材质，可点“白模对照 / 恢复材质”切换。包括木材、深色金属、钢、聚合物、橡胶、沙色金属，共 6 种；11 个零件型号具有 32 个具名区域。例如枪托木质主体和橡胶尾垫可分别换材质，护木两端接圈也独立指定。

模型、材质和工作台交互已于 2026-09-13 获用户确认并提交（`c95658b`）。之后新增的真实武器显示及第一人称修复，正式效果仍由用户另行验收。

## 文件各管什么

| 文件 | 用途 |
| --- | --- |
| `src/main/resources/assets/weapon_assembly_ui/materials/basic.json` | 材质库：颜色、贴图、粗糙度、反光强度、纹理重复比例 |
| `src/main/resources/assets/weapon_assembly_ui/textures/materials/` | 原创 PNG 图像 |
| `src/development/resources/assets/weapon_assembly_ui/materials/adar.json` | ADAR 零件默认材质和区域覆盖 |
| `src/development/resources/assembly-adar/manifest.json` | 运行时几何、区域名称和 UV（贴图坐标） |
| `material-authoring/ADAR-original-materials.bbmodel` | 可用 Blockbench 编辑的副本 |
| `tools/adar-regions.json` | 从原始白模重新生成时使用的初始分区规则 |

材质选择顺序为：**区域覆盖 → 零件默认 → 全局默认**。外观配置由界面宿主读取，组装算法、配件属性、兼容性和实例身份不受影响。

## 后续换颜色或贴图：不用 Blockbench

在 `basic.json` 的 `materials` 对象中增加一个材质，例如纯色绿色涂层：

```json
"green_paint": {
  "baseColor": "#657552",
  "roughness": 0.75,
  "specular": 0.15,
  "textureScale": 1
}
```

也可以添加 `"texture": "weapon_assembly_ui:textures/materials/my_pattern.png"`，把自己的 PNG 放到相应目录。颜色会乘到图片上；要保留图片原色，使用 `#FFFFFF`。当前支持不透明材质，先使用完全不透明的图片。

在 `adar.json` 中找到零件 ID：修改 `defaultMaterial` 改默认材质；修改 `regions` 中某个名称，只替换该区域。例如把枪托的 `butt_pad` 从 `rubber` 改成 `green_paint`。已有区域覆盖不会因为默认材质改变而消失，想让区域跟随默认就删除对应覆盖项。

保存后重新运行工作区根目录的 `启动组装测试客户端.command`，资源会重新复制并加载。不需要重新导入模型。不承诺当前已打开页面即时刷新。

如果还要更新真实武器与配件图标，在 NewMod 根目录运行 `python3 source/mods/tacz_adapter/tools/build_adar.py`，再重启开发客户端。只重启组装样本不会更新已复制到 `newmod_adar` 的绑定与图标。生成器需要 Pillow、NumPy；当前材质 PNG 由 `weapon_assembly_ui` 正式资源提供，不能把该运行依赖当作只有开发时才需要。

## 调整区域或 UV：使用 Blockbench

1. 打开 `material-authoring/ADAR-original-materials.bbmodel`，先另存副本。
2. 网格名称就是区域名；不同区域可分配不同的材质贴图。贴图文件名去掉 `.png` 必须等于材质库 ID，例如 `steel.png`。同一零件内同名区域应使用同一种材质。
3. 可以调整 UV；需要更细的区域时可以把已有面分到独立网格并命名。保留原有面 ID、顶点 ID、几何坐标和零件顶层组 UUID。不要修改模型形状、变换或隐藏状态。
4. 保存后，在工作区根目录先检查，再导入：

```sh
python3 source/mods/weapon_assembly_ui/tools/import_material_project.py /绝对路径/编辑后的.bbmodel --check
python3 source/mods/weapon_assembly_ui/tools/import_material_project.py /绝对路径/编辑后的.bbmodel
```

导入器先校验整份文件，拒绝新增/删除面、几何变化、未知材质及无效 UV，然后更新运行时区域、UV 和材质绑定。重新启动客户端查看。需要修改形状时应走模型修订流程，这个入口只接收外观调整。

**Blockbench 内嵌图片是带基础色的预览副本。** 此导入器读取分区、材质分配和 UV，不把内嵌图片覆盖到运行时 PNG。绘制新纹理时应保存到上面的资源目录并在材质库中引用，避免颜色被重复叠乘。Blockbench 预览与客户端的灯光、高光表现可以不同。

## 工具与重新生成

日常使用只需要客户端。资源修改使用文本/图片编辑器；分区和 UV 修改使用 Blockbench。MCP 是代操作入口，已经导出的模型运行不依赖 MCP。

`tools/export_material_project.py` 从白模和分区规则生成 Blockbench 工程副本，并读取材质库中的实际 PNG。它支持自定义 PNG 和无贴图纯色材质；这个导出工具需要 Python 的 Pillow，运行客户端不需要。执行前备份已有编辑，因为导出会覆盖工程副本，而且不会保留之前在 Blockbench 中手工调整的分区和 UV。

`tools/import_adar.py` 从原始白模重建运行时几何、初始区域和 UV；`tools/generate_materials.py` 重建最初 4 张原创纹理。它们是重建工具，**换材质时不要顺手全部重跑**，否则会覆盖相应手工修改。纹理生成来源与 SHA-256 记录在 `tools/material-provenance.json`。

本批只读取提供的白模几何，新 UV 和纹理自行生成，没有使用塔科夫原贴图或原 UV。当前粗糙度/反光强度控制的是简易展示高光，并非完整 PBR；玻璃透明、环境反射、动画不在本批范围。未来材质增加通常只需扩充材质库与绑定；新的光照效果才需要扩展渲染器。

## 雷电与后续矩阵组件

雷电使用 `source/mods/tacz_adapter/weapon-authoring/radian/`：`library.json` 管材质和颜色，`materials.json` 管型号默认/区域覆盖，`import.json` 的 `regionRules` 管尾垫、底板等共同坐标分区。所有型号身份和材料选择在配置中，不在 Java 中按枪名分支。

当前原创纹理由 `tools/build_weapon.py` 的确定性纹理生成器生成，固定种子保存在 `import.json`。细颗粒、多尺度色差和少量方向纹理控制表面变化，颜色只在运行时乘一次；金属、聚合物、橡胶分别使用不同明度和材质参数。部件原 UV 被保留，不使用原游戏贴图。这里提供的是基础色与简易光照适配，不宣称完整 PBR 或真实表面还原。

改好配置后，在 NewMod 根运行：

```sh
python3 source/mods/tacz_adapter/tools/build_weapon.py source/mods/tacz_adapter/weapon-authoring/radian
```

运行资源和图标会同步生成；不要手改生成 PNG 后又执行生成器覆盖它。雷电目前不走 ADAR 的 `import_material_project.py`，后者依赖 ADAR 的固定面身份与分区工程。新枪如交付现成材质，应扩展通用生成器的图片输入分支，保留对应 UV/贴图引用，不顺手重生成原创纹理替代交付内容。

雷电材质静态预览与状态见[批次说明](../../../docs/参考资料/radian-20260914-data/README.md)。本次按用户要求只编译；真实持枪光照、机瞄和材质美观由用户进游戏验收。
