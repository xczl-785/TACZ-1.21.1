# 独立武器能力

定位：组装结构和能力规则由独立模块拥有，TaCZ 适配器负责执行。TaCZ 的动画、装填、射击继续复用；将来更换武器实现时，在新适配器中消费同一能力结果。

| 模块 | 职责 |
|---|---|
| `weapon_assembly` | 纯 Java 兼容规则、结构校验、关键路径判断 |
| `weapon_runtime` | 将 foundation 的真实装配组件投影到算法，判断结构是否允许射击 |
| `tacz_adapter` | 在 TaCZ 开火入口和每次实际击发前执行禁止规则 |
| `weapon_assembly_ui` | 工作台展示与操作意图；本批尚未连接实枪 |

依赖方向为 `tacz_adapter → weapon_runtime → weapon_assembly / foundation`。独立规则不引用 TaCZ、战术库存或界面；没有第二份配件库存。

## 当前合同

宿主注册 `WeaponCapabilities.Profile`：武器标识、算法目录、根定义、物品到配件定义的映射，以及射击所需的槽位路径。物品上的 `weapon_runtime:profile` 只保存配置引用；真实子件继续保存在 `item_foundation` 的 `AssemblyComponents.STATE` 中，沿用其保存和网络同步。

`WeaponCapabilities.firing` 输出是否接管、结构是否允许射击、拒绝原因。未标记的武器保持原行为；已标记但配置缺失、武器标识不匹配、关键部件缺失/禁用或结构非法时禁止。装配目录中的所有“必需槽”不会自动成为射击条件，例如缺弹匣不应直接否定已上膛的一发。弹药、冷却、保险、装填等动态条件仍由武器实现判断。

TaCZ 服务端在五参数 `LivingEntityShoot.shoot` 入口拦截，覆盖普通及蓄力入口，早于弹匣向枪膛转移。`GunFireEvent` 再对每次击发复核，覆盖延迟/连发路径。客户端提前阻止预测并显示提示；服务端保持权威。签名以当前锁定的 `8497fd29` Jar 验证，升级 TaCZ 时必须重跑验证。

## 第一项：真实枪管验证链

开发配置仅接管 `/assemblyfire kit` 领取的 Glock，不会批量接管原有枪械。枪管参考定义来自 EFTForge 的现有 Glock 测试目录；测试 Item 仅是 1×1 的诊断物品，使用铁锭图标，不代表正式模型或尺寸定稿。所有测试注册、配置、命令和图标都不进入正式 Jar。

日常使用根目录 `启动开发客户端.command`，进入原开发世界：

1. `/assemblyfire kit` 领取已装枪管和弹药的测试 Glock，将它持在手中。
2. 开火确认正常；`/assemblyfire remove` 拆下枪管，真实零件进入随身库存。
3. 再开火应被禁止，弹药不变；`/assemblyfire status` 可看当前能力结果。
4. `/assemblyfire install` 消耗随身库存中的兼容测试枪管，恢复射击。

要求 OP 2 开发权限。返还空间不足时整笔拒绝，枪管留在枪上；安装不生成免费配件。当前仍显示 TaCZ 原有完整枪模，工作台中的样本枪也尚未关联此实枪。
