# 算法合同

用途：下一批界面/适配器与测试消费者的公共合同。源码 `dev.weaponassembly.api` 为权威；版本目前 `0.0.0-dev`，不承诺跨开发构建二进制稳定。JSON schema 为 1，不兼容版本显式拒绝。

## 数据与身份

`PartDefinition` 是型号定义，包含自身槽、允许型号、必需标记、物品冲突、槽冲突、自身属性，以及可选武器基值。`AssemblyCatalog` 一次创建不可变目录，检查重复 ID、悬空允许项/冲突引用，禁止把武器根当配件。目录更新使用新对象和新引擎；旧引擎不受隐式全局重载影响。

`AssemblyNode(UUID instanceId, String definitionId, Map<String, AssemblyNode> children)` 表示一次物理出现。UUID 由宿主提供；引擎不分配或替换身份。同型号可以装在不同槽，但每个实例只允许出现一次，根也在检查范围内。输入 map 防御复制，子槽按名字排序。

定义兼容图允许反复出现同型号（比如转接件），实例树必须有限且无重复 UUID。实例规模上限是根深度 0、最大深度 8、总节点 129，与现有 foundation 的 128 个模块加根对应。超限拒绝，不截断或返回看似完整的部分树。

## 校验和操作

`validate(root)` 可校验枪根或独立子组件。`errors` 表示结构不合法；`missingRequired` 表示已存在的各父件缺少必需槽。完整性是树上逐个实例检查，不用型号集合推导，也不会把尚未安装的可选父件的子槽算成缺失。

- `install(root, path, source)`：目标必须为空，source 可以自带子树。
- `replace(root, path, source)`：目标必须占用，返回旧件整棵子树。
- `remove(root, path)`：返回目标整棵子树；缺必需件不阻止拆卸。
- path 是从根起的槽名序列，比如 `[mod_reciever, mod_scope]`；空路径不能拆换根。
- 原树与 source 都先验证；任何 source UUID 与原树重叠都拒绝，包含替换下来的旧件。树内挪动应先独立拆卸再安装，实际资产是否一次提交由宿主决定。
- 成功结果：`before`、`after`、可选 `detached`；失败结果：`after` 与 `before` 是同一原树、无 detached、有结构化 `Issue(code,path,detail)`。
- 操作只创建计划，无版本计数、库存预留、世界写入或副作用。目录发生变化后应丢弃旧计划并重新计算。真实提交必须重新校验旧状态/租约，并同时处理 source 扣除、detached 返还及枪更新。

`PART_CONFLICT`：任一方声明互斥即冲突，包括跨分支和父子，同型号不同实例也参与。
`SLOT_CONFLICT`：已安装件阻止一个“父型号 + 槽名”的槽被占用；同父型号的每个实例均检查。空槽不冲突，但如果该槽必需则完整性仍不足。不能只按裸槽名匹配所有父件。

本批不含开关配件状态、槽位之间的依赖/互斥扩展、发射组件类型或动画状态。`complete()` 只代表声明的必需槽齐全，不能代替装弹、枪膛、耐久和忙碌等射击检查。

## 属性口径

`new WeaponStats(engine).calculate(root, Context)` 要求合法武器根，但允许未完成装配，用于拆装预览。未知或非法结构拒绝计算。Context 是调用者传入的力量等级 0—51 与装备人机修正 -1—1，不读取 NewMod 人物系统。

| 属性 | 计算 |
| --- | --- |
| weightKg / ergonomics | 根本体加每一个已装实例；同型号两件累计两次 |
| recoilVertical/Horizontal | 武器基值 × (1 + 所有 recoilFraction 之和)；-0.03 表示 -3% |
| accuracyMoa | 34.36 × COI × (1 - accuracyPercent 总和 / 100) |
| COI | 已装非根部件的 COI 覆盖武器基值；该部件自身 accuracyPercent 不叠加；多个覆盖者明确拒绝 |
| sightingRange | 武器基值和已装部件的最大声明值；全未知则 OptionalDouble.empty |
| velocityPercent | 初速百分修正之和；尚未选弹药，不返回真实初速 |
| heat/cooling/durabilityBurnFactor | 所有实例系数相乘，默认 1 |
| EED / overswing | E = 人机 × (1 + 装备修正)，KG = 0.0007556 E² + 0.02736 E + 2.9159；EED = -15 × (重量 - KG)，重量 > KG 时 overswing |
| armStamina | ((85.5/(重量+0.65)) + 9.15 + 0.06477×人机×(1+装备修正/2)) / 1.04 × (1+力量×0.004) |

未知 COI 返回空，不编造精度；已声明的 0 是 0。输入/输出拒绝 NaN、无穷与负物理结果；无界相加/相乘溢出失败。不做显示舍入，UI 可自行格式化，但不得把格式化结果写回权威值。

公式参考 EFTForge `backend/stats.py`，归属说明与许可在 Jar 的 `META-INF/licenses/EFTForge-MIT.txt`。有意区别：只接受本体/自身数值，不采用 factory_intact 预计算捷径，不自动加满弹匣，不按型号去重，不用遍历顺序选择多个枪管，也不在核心套用 Python 显示舍入。因此不是 EFTForge 全 API 的逐字段复刻。

## JSON 目录与快照

`AssemblyJson.readCatalog(String)` 接收已归一化目录；不直接接收 tarkov.dev 原始 JSON。未知字段、重复字段、错误类型、悬空引用都拒绝。缺省数值贡献为 0、乘数为 1；缺省可选数值表示未知；null 不作为缺省。

```json
{
  "schemaVersion": 1,
  "parts": [
    {
      "id": "example:gun",
      "slots": [{"id": "optic", "required": false, "allowedParts": ["example:sight"]}],
      "stats": {"weightKg": 1, "ergonomics": 50},
      "weapon": {"recoilVertical": 100, "recoilHorizontal": 150}
    },
    {
      "id": "example:sight",
      "stats": {"weightKg": 0.1, "recoilFraction": -0.03, "sightingRange": 150}
    }
  ]
}
```

可选 `conflictingParts` 是型号 ID 数组；`blockedSlots` 是 `{ownerDefinition,slot}` 数组。slot 的 `required` 默认 false。weapon 的两轴后坐力必填，其余字段与上述属性表一致。

`writeSnapshot(root, engine)` 输出 `{schemaVersion:1,nodes:[...]}`；每行包含 instanceId、definitionId，子行另外包含 parentId、slot。父先子、同层按槽名，编码确定；读取拒绝孤儿、重复占位/身份、未来 schema、非法装配。导入后继续执行完整规则校验，未完成但合法的组件允许保存。

JSON 输入最多 1,048,576 字符、语法嵌套 32 层；这不是全量 EFT 数据导入器。快照不保存耐久/弹药/任意 ItemStack 组件，不能拿它替代真实物品存档。

## 数据样本

`src/test/resources/glock-optics.json` 是本地 EFTForge 缓存中的 Glock 17、ZEV 套筒、RMR、标准枪管四件切片，保留所有源槽及 required 标志，只保留指向四件的允许边。空候选槽不会被伪造填满。它不是全量兼容清单或三维资源。

来源与 SHA-256 见 [fixture-source.json](fixture-source.json)。在工作区根复现：

```sh
python3 source/mods/weapon_assembly/tools/generate_reference_fixture.py EFTForge/docs/data/cache/items.json
```

生成器显式归一化源字段，尤其 `properties.recoilModifier` 是小数比例、`properties.accuracyModifier` 乘 100 转百分数。人工定义的分支/冲突数据与真实切片分开，人工数值不冒充真实枪械资料。
