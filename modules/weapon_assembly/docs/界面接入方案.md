# Gunsmith 界面接入方案

2026-09-13：原型调查与 NewMod 组件映射已完成，Minecraft 隔离界面现已实现，运行入口见 [界面模块 README](../../weapon_assembly_ui/README.md)。本页是后续实施入口；原型细节见 [gunsmith原型梳理](gunsmith原型梳理.md)。

## 确定的设计合同

用户确定：使用 NewMod 其他 Mod 使用的标准界面库，控件风格一致；不采用手绘风格。保留原型的信息布局与操作流程，样式以本工程公共主题为准。当前依赖是 LDLib2 2.2.37（`source/gradle.properties`）。

保留：整屏枪械预览、左上名称、左下当前属性与候选差值、部位旁配件浮窗、右下撤销/恢复默认/复位视角。点标签选择部位，悬停只预览，点击提交；空白点击关闭浮窗，拖动旋转不能误触关闭。候选较多时滚动；窗口与标签位置按实际 GUI 坐标和视口裁切。

## 公共组件映射

以下类均在 `source/mods/foundation/src/main/java/dev/itemfoundation/client/api/`。Tactical 的 `GearDesign` 已继承 `UiDesign`，组装界面应直接消费公共 API，不为取样式依赖 Tactical 内部类。

| 原型区域/行为 | NewMod 落点 |
| --- | --- |
| 页面与浮窗层级 | LDLib2 UIElement + InventoryRootElement；页面 PAGE、配件浮窗 MENU、反馈 NOTICE；共享绘制/命中顺序 |
| 配件浮窗标题、关闭 | InventoryWindowElement / InventoryWindowChrome；按投影锚点放置并限制在可视区域 |
| 部位标签、安装、拆除、撤销等 | InventoryButtonElement；复用启用、禁用、悬停、按下状态 |
| 名称、属性、差值、错误原因 | InventoryTextElement、UiDesign.text；颜色取 InventoryUiTheme，不能仅靠红绿表示结果 |
| 候选列表 | InventoryScrollView；候选卡用普通 UIElement 组合公共文本/按钮/表面 |
| 背景、边框、字号、缩放 | InventoryUiTheme、InventoryUiSkin、InventorySurfaceTexture、UiDesign；统一换算一次 |
| 真实物品缩略图 | InventoryItemRenderer；没有 ItemStack 的模型夹具不能伪装已有正式物品 |
| 可旋转整枪及标签投影 | 需要专用三维视口；现有 InventoryItemRenderer 是物品展示入口，未提供任意装配树相机与挂点投影能力 |

三维模型允许通过模型渲染绘制；界面面板、按钮、文字仍使用标准控件，不通过手画按钮或整屏贴图替代。原型 Web 字体、CSS、Three.js 数值及固定 260px 浮窗宽度不机械照搬。

## 模块职责建议

推荐新增伴随界面模块 `weapon_assembly_ui`（已创建），依赖 `weapon_assembly` 与 `foundation` 公共 UI/LDLib2。`weapon_assembly/api` 继续独立于游戏框架；foundation 不反向依赖武器算法；不修改现有算法边界检查来允许 UI 混入核心。

界面接收只读状态、候选查询和操作回调；视口负责模型挂点、相机、选中及投影。开发宿主提供样本会话，实际库存宿主后续通过服务器事务实现同样回调。模型资源与规则目录分别加载，不根据几何碰撞猜测兼容。

这比把 UI 加进算法 Mod 多一个模块，但保留了纯算法可独立使用、界面可独立运行的边界。正式玩家仍看到一个组装流程。

## 补齐原型没有覆盖的场景

- 选择键使用完整槽路径和实例 UUID；同型号两件不串选。先显示当前层槽位，选择有子槽的配件后可进入下层，提供标准返回/路径控件，避免一次铺满所有递归标签。
- 悬停由引擎生成临时计划和属性，不改变已提交树或历史。非法候选显示原因，不显示为可提交的成功预览；提交失败保持旧模型。
- 必需件可拆，显示缺失路径及“不完整”，遵循算法合同。
- 样本会话保留 detached 整棵子树，撤销恢复整份会话，不能只恢复枪而遗漏拆下的配件。真实库存阶段的撤销必须重新校验交换，不直接写历史快照。
- 枪名、属性和槽位来自数据；当前首批使用已有 Glock 复杂夹具，不照搬原型 M4 的硬编码六槽和数值。

隔离客户端优先使用薄测试宿主，只加载界面、算法、foundation 及其必需依赖，消费同一正式界面代码。若可无世界打开则从主菜单进入，否则专用测试世界；不复用 `runs/tactical-client`。算法 JVM 测试继续保留。

UI 实现后需要实际 Minecraft 启动、连续操作及不同 GUI 缩放检查，并由独立审查者核对原型行为与标准控件落点。自动证据不能替代所有者最终实机手感验收。原型调查阶段未运行浏览器；实现阶段已补充 Minecraft 隔离客户端工程检查。2026-09-13 所有者明确正式验收与测试由本人负责，工程检查只保证打开及所覆盖的功能链正常。
